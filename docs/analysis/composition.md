# 创作路径（Composition Flow）🚧 设计

> 状态：**分层缩谱工作区与最小素材台已实现；主谱/缩谱直接提取的简化仍为 🚧，
> 现有内容线路由作为兼容实现保留。** 总览见 [README.md](README.md)，
> 数据基础见 [reduction.md](reduction.md)（缩谱与 NoteLink）。

## 1. 理念：创作路径 = 持久化的层级栈

分析自上而下还原，创作自下而上实现，二者共享同一层级栈：

```
曲式计划（form 轨草图 🚧 远期）
  → 和声进行（和弦轨 / 骨架）
  → 分层缩谱（曲式 / 和声 / 骨架 / 记谱）
  → 演奏者 / 谱表分配（内容线仅作内部兼容路由）
  → 总谱（书面实现，双段 NoteLink 记录每一笔的来源）
```

"保留创作的完整路径"即：**每一层都是作品文件中的持久数据，实现下一层不销毁上一层**。
写完的和弦进行、缩谱不是草稿纸，而是总谱的对照物与后续修改的杠杆。这也是
`WritingTaskPlan` 多阶段求解（writing-engine）的人工版本——机器求解与人工创作
走同一条层级栈，因此求解器可以在任意一层介入（§5）。

## 2. 对照创作

**写总谱时对照和弦进行**：和弦轨（`mecon.chord_analysis`）挂在总谱或缩谱上，
注释谱表常显；总谱音符按当前和弦做和弦音/外音着色（`ChordToneStyleProvider` 既有
能力），写作时即时看到哪些音落在计划的和声之外。

**写总谱时对照缩谱**：对照视图 = 编辑器分屏——主区总谱照常编辑，下方停靠当前
活动缩谱的对应时间段，滚动与播放头经 `ReductionAnchor` 时间平移同步。
依赖 exploration E2 的多乐谱宿主（`ActiveScoreContext` + per-score 渲染管线）；
缩谱侧同样可编辑（lens 提交，单撤销栈，见 reduction.md §6）。

**偏离语义**：对照不是强制同步。总谱有意偏离缩谱（装饰、临时变奏）时，
`PITCH_DIVERGED` / `UNMAPPED` 着色只是提示；用户选择"更新缩谱跟随总谱"、
"重新对齐 link"或"接受偏离"（intentional 标记 🚧 v2）。反向亦然：改缩谱里的
和声计划后，总谱侧立即显示哪些已写内容需要跟进——**偏离标记就是跨层的 todo list**。

## 3. 从缩谱到总谱：实现（Realize）

创作方向的目标操作与分析方向的“提取”互为逆操作；缩谱不直接绑定总谱。第一阶段 UI
已经把配器显示为谱面演奏者标签，但写入仍复用原内容线引擎：

- **绑定选段**：选中缩谱某声部一段 →"绑定/配器"→ 新建/选择内容线 → 选择一名或
  多名演奏者 → 分别指定谱表 / voice。先生成内容线音符与 `StorageReduction.links`，
  再写 `StoragePerformance` / `StorageStaffAssignment`。
- **写入总谱**：按内容线在当前时刻的演奏者和谱表分配生成书面音符，并建立
  `StorageOrchestration.links`。换演奏者或调整谱表时无需改缩谱链接。
- **齐奏 / 八度重复**：一次实现可指定**多个目标**（如"长笛 +8va、双簧管原位、
  大提琴 -8va"），产出多组音符、多组 link 指向同一缩谱音——polyphony todo 的
  "多对一 + 八度位移"在创作方向的形态。
- **待办驱动**：缩谱侧 `UNREALIZED` 状态（reduction.md §4）列出"尚未绑定内容线"
  的音符；面板按声部/时间聚合成配器进度清单。
- **先缩谱后挂载**：独立创作的缩谱（`anchor == null`）经"挂载到总谱"补 anchor
  （指定总谱起点，v1 要求拍号兼容），随后逐段实现。

实现操作走主文档撤销栈，一次实现（含多目标）为单个原子提交。

## 4. 更换配器与试听

> 本节操作的完整落地设计（演奏者/内容线模型、时变分配、播放路由）见
> [orchestration.md](orchestration.md)——realize 目标由"staffTrack/voice"泛化为
> "内容线 + 谱表分配"，改配器成为纯路由数据（`StoragePerformance`）的编辑。

- **改配器**：选中一段已实现内容（总谱选区或 link 集合）→"移到另一乐器"：
  音符迁移到目标 staffTrack（保持 pitch/duration/onset，可附加八度位移，记谱按
  目标乐器移调重排），**link 保留**——缩谱视角下只是"这段旋律换了演奏者"。
- **增删重复层**：对同一缩谱段追加实现（加一件八度重复乐器）或删除某一目标的
  实现（音符与 link 一并删除），配器厚度随时调整。
- **试听对比 v1**：走撤销栈 A/B——应用配器方案、播放、Ctrl+Z、换方案再播。
  简单可靠，先验证工作流。
- **配器变体 🚧 v2**：同一缩谱段并存多个命名实现方案（variant），播放时静音
  切换、谱面单显活动方案。与 exploration 候选对比（chip 切换）同题，UI 形态
  待 v1 使用反馈后定；数据上 variant = link 分组标签，模型改动小，故推迟。

## 5. 求解器与探索模式接缝

- **求解器介入任意一层**：缩谱声部作为 `WritingTask.fixedMaterial`（给旋律配和声、
  为主题写对位）；骨架 + 装饰两阶段（figuration）产出的结果落到缩谱层；
  配器建议 🚧 远期。求解输出遵循 ai/roadmap "建议 + 用户确认"约束，确认后写入
  对应层并建立 link。
- **在探索模式中打开**：选中缩谱（或总谱选区）→ 新建探索文档，首 cell 为导入材料
  （exploration README §4 既定路线）。实验满意的结果通过"实现/写回"落回作品文件。
  `MaterialRef` 增加来源锚形态 `SourceRef(file, reductionId?, timeRange)` 🚧，
  使探索 cell 记住素材出处。
- **临时和弦、外音分析**（reduction.md §7）在创作方向的用法：写完装饰后跑还原
  检查，确认装饰没有改变计划和声——生成与检查共享判定器（figuration §4 原则）。

## 6. 开放问题

- 对照视图的布局（下方停靠 vs 右侧 vs 画中画）与多缩谱切换交互；
- 改配器时演奏法/力度等 staff 附着符号是否随迁（v1 只迁音符，附着符号提示手动处理）；
- 配器变体与播放 mixer 的关系（variant 静音是数据态还是播放态）；
- 实现操作生成音符与总谱既有内容冲突（同 voice 同 onset）的合并策略：v1 拒绝并
  提示选择其他 voice，自动挪声部 🚧；
- 曲式计划层的创作形态（先画空白分段再填内容）依赖 form 轨在无音符区间的渲染，远期。
