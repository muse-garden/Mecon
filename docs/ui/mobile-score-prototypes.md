# 移动打谱交互原型与评审清单

> 状态：🚧 九个交互家族均已有 Android 可执行审阅原型；评审 3/4/6 已确认，其余项继续按 APK 反馈收敛。
> 规范来源：[交互分类与接口](score-interaction-taxonomy.md)与[移动端方案](mobile.md)。

## 1. 原型范围

同一可交互原型提供 Phone、Pad、Pencil 三种呈现，并可逐类切换 N/E/P/S/G/T/B/H/F。它验证信息架构、
状态反馈和手势等价性，不验证字体排版精度、真实 renderer 性能或最终视觉品牌。

所有场景使用同一首屏结构：

- Phone：顶栏 + 聚焦谱段 + 当前模式/读数 + 常驻工具组横排 + 上下文操作 + `记录/编辑/分析/试听`；
- Pad：顶栏 + 左家族工具轨 + 中央谱面 + 右 inspector/候选区 + 可调底部输入区；
- Pencil：沿用 Pad，改变 hover、第一次命中与直接拖动语义，不产生第三套 command。

原型中的“完成”只代表会发送一个 intent；“取消”代表丢弃 preview、revision 不变。

## 2. 共用视觉与状态

| 元素 | 语义 |
|------|------|
| 蓝色/主色轮廓 | 当前稳定 selection 或活动 mode |
| 灰色半透明记号 | 尚未提交的 ghost/候选结果 |
| 实心圆手柄 | 可拖的 start/end/body/control；选中前不显示 |
| 垂直虚线 | `TimeCode`、小节边界或吸附候选 |
| 顶部短标签 | 音高、拍位、measure range、声部或目标名称 |
| 底部“取消/完成” | 所有两阶段/多阶段交互的一致出口 |
| “− / +”与属性 | drag 的确定性替代；使用同一草稿与一次提交 |

候选分数接近时，Phone 弹出紧凑候选 sheet，Pad/Pencil 在目标旁显示 callout。`CommitPending` 保留 ghost
并阻止第二次编辑，完整帧到达后才恢复；stale/失败回到权威帧并显示重试。

## 3. 九个家族的原型脚本

### N 导航、选择与历史

- 初始：编辑活动，未选中；手指拖空白平移，Pencil/鼠标 hover 只高亮候选。
- 动作：点音头选中；进入显式多选后再点两个对象；框选只在 Pad 可直接拉，Phone 用“多选”入口。
- 反馈：稳定选择有大 halo；底部显示删除/复制/移调/更多；undo/redo 常驻顶栏。
- 验收：空白点击、追加/移除、撤销恢复 selection、候选歧义和辅助技术顺序均可理解。

### E 连续记谱

- 初始：记录活动，焦点系统内有 `staff/time/voice` 光标；钢琴上方显示时值、附点、休止、tie、声部。
- 动作：按琴键插入单音；开启和弦 latch 后按多键并点“写入和弦”；grace 作为输入修饰符。Tuplet 先按
  “数目 + 总时值”创建全休止范围，再从范围起点逐音填入，不与首音同一次创建。
- 反馈：按下只 audition/显示 ghost，提交后光标只跟随 `nextInputPosition`；one-shot 参数消费后回显。
- 导航：常驻提供上一/下一音符、上一/下一小节；手动移动后下次插入从新光标继续。
- Phone：钢琴占底部半屏；Pad 可调高度；Pencil 点谱面是显式 note tool 的另一 adapter。
- 验收：输入/试听模式清楚，快速输入不重复提交，和弦一次历史，外接 MIDI 不改变当前活动。

### P 单点放置

- 初始：从“符号”选择 `mf`，模式条显示“放置力度 · 单点”。
- 动作：移动/点到谱表时间；候选为音头 onset、相邻边界或小节线；确认一次。
- 反馈：ghost 与竖向吸附线同步；Phone 首次 tap 预览、再次“完成”，Pencil 抬笔可直接提交。成功后保留
  当前工具组，但清空落点，下一次必须重新选择位置。
- 验收：替换为谱号/调号/拍号/速度/fermata/breath/ornament 时流程不变，只换参数与目标过滤。

### S 区间放置

- 初始：选择渐强线；点按左端点后立即显示一个默认四分音符长度（不可用时取同系统最近可渲染拍位）的完整符号。
- 编辑状态：符号左右端各显示一个方形手柄；空心表示可选，实心表示当前活跃端点。首次点按左端点后，右端点自动活跃。
- 动作：可从首次左端点按下后向右拖；也可在右端目标位置完成第二次点按。已有草稿可直接拖任一端点，或先点端点使其变实心、再点目标位置迁移该端点；结束必须晚于开始且保持同一 staff。
- 反馈：拖动与第二次点按都只更新 renderer ghost 和语义锚点；底部“完成”才发送一个共享 intent，“取消”保持零历史。
- Phone/Pad/Pencil 共享上述状态机，只调整手柄命中半径与 hover。成功后保留当前工具组，清空 start/end，下一次重新建立草稿。
- 验收：slur、8va、渐变速度、区间 trill 只更换 target/preview policy；cancel 零历史。

### G 组选区构造

- 初始：选中同声部、同小节的完整事件范围，用于改造已有材料或建立小音符区域。
- 动作：已有材料可选择 N 转成 tuplet；小音符先选区间并建组，不在 UI 计算时值拆分。
- 反馈：组边界与成员编号同时可见；preview 来自共享编辑/渲染能力。
- 验收：一次提交、一次撤销；小音符建组成功后自动切到 E，并把光标/append anchor 指向组起点。

### T 选区变换

- 初始：选择若干音符；底部常用 action，更多进入 sheet/inspector。
- 动作：点移调 `+1`、时值、变音、tie、符杠、声部、演奏法或琶音；破坏性动作需清楚的目标摘要。
- 反馈：可预览的操作先显示结果，不可预览的 toggle 显示新状态；批量结果只提交一次。
- 验收：按钮、快捷键、nudge 与表单产生同一 intent；混合/不可编辑选择禁用且解释原因。

### B 结构边界与范围

- 初始：进入“结构”，小节线触控目标扩大，显示 boundary measure；普通音头暂不参与候选。
- 动作：选边界设置小节线/导航/房子；增删小节与谱表可见性先显示受影响 measure range。
- 反馈：结构重排区着色，提交后保持旧完整帧保护；Phone 默认二次确认，Pad 可用 inspector 完成。
- 验收：分页行首/行末同一逻辑边界不重复；跨系统只按指针所在 staff core 选系统。

### H 语义手柄

- 初始：先选择已有 slur；出现 start/end/body 三类手柄，当前家族和锁定轴可见。
- 动作：拖端点吸附事件、拖 body 改弧高；切换 `−/+` nudge 可完成同一草稿。
- 反馈：隐藏旧对象、实时 ghost、目标连接线与数值；抬起后保持 preview 到完整帧。
- Phone：第一次只选择，第二次拖外扩手柄；只承诺语义移动、nudge 与常用属性，不要求横屏精细
  engraving。Pencil 可直接拖精确手柄。
- 验收：tie/beam/articulation/attachment/volta/navigation/音高/休止复用生命周期且各自锁轴正确。

### F 属性表单

- 初始：选中 tempo/ornament/fermata；sheet/inspector 从 descriptor 生成适用字段。
- 动作：修改 BPM、显示样式、辅助音变音或时长；中间字符串只留在本地草稿。
- 反馈：有效值可显示共享 preview；Enter/完成/失焦只选择一个统一提交点，取消恢复权威值。
- 验收：动态字号与软键盘不遮住选中对象；同类多选显示共同值/混合值；无 drag 也可完成全部编辑。

## 4. 跨家族异常场景

原型评审同时检查：

- 两个候选同分：必须让用户选择，不能猜；
- 第二 pointer、系统返回、切活动、旋转、切后台：取消 preview，保留 selection/插入光标；
- stale revision：不发送旧坐标重试，重新解析权威帧；
- session `NO_OP/CONFLICT`：说明原因，不伪造成功；
- 提交慢：ghost 保留、编辑锁定、播放/导航按明确 policy 处理，不闪回旧对象；
- 已存在但手机不能编辑的元素：可选择、可解释、可无损保存，并标出 Pad/Desktop 编辑入口。

## 5. 评审问题

评审需逐项记录“接受 / 调整 / 后置”：

1. 九个家族及 57 intent 的主要归属是否稳定？
2. Phone 的“记录/编辑”分工是否足够清楚，是否需要常驻直接落音工具？
3. ✅ P/S 成功后保留工具组但重置位置；E 保持 armed 并自动前进，另有前后音符/小节导航。
4. ✅ 新 tuplet 属 E：先创建“数目 + 总时值”的空范围，再填音符；小音符先选区建组，成功后切 E。
5. B 在手机上默认二次确认是否过重，结构入口是否可发现？
6. ✅ 接受“手指两步、Pencil 直接”；Phone 不要求横屏精细 engraving。
7. Pad 右 inspector 与底部输入区的并列关系是否合适？
8. 候选 sheet、commit hold、stale/error 的反馈是否足够明确？
9. drag 的 nudge/属性替代是否覆盖运动障碍和屏幕阅读器路径？

## 6. 评审后的交付门禁

评审通过后先更新本文与 taxonomy 的最终决定，再进入移动 M0。实现 PR 必须逐家族引用已确认的原型状态，
并把视觉变化与业务协议变化分开评审；未通过的家族不得以临时平台手势先行落地。

当前 APK 让上述评审从静态脚本进入真实 renderer/session 流程：P/S 使用 renderer ghost，N/B/H 使用
renderer 命中、区域索引或捕获几何，所有确认动作进入 `ScoreEditingSession`。固定示例已改为参数行和和弦
latch；N 框选、候选菜单、H 连续 ghost 拖动、G/B 草稿确认及 nudge/表单替代均可执行。Pad/Pencil 的
hover 放大镜、空白拖动与多系统范围拖选仍需设备实测调整，但不得改变这些共用语义状态与一次提交边界。
