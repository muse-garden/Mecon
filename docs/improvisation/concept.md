# 即兴模块概念背景（讨论记录）

> 本文是即兴模块立项前的概念讨论记录，保留原始论述与外部文献引用，**不是实施方案**。
> 具体可落地的架构设计见 [design.md](design.md)，开发路线图见 [roadmap.md](roadmap.md)。
> 文中"平板优先"、"两拇指操作"等交互设想已在设计阶段按桌面端现状调整（design.md §10）。

## 一、先换一个角度理解“即兴”

爵士与巴洛克即兴都不是在每个十六分音符到来时，临时从十二个音里挑一个。更接近于：

> 在既定风格、曲式和当前上下文中，实时选择下一种音乐行为，再用已经掌握的句法与素材把它实现出来。

研究爵士乐手的即兴思维时，常见策略包括调用熟悉的乐句、优先考虑旋律走向、优先考虑和声目标，以及重复并发展刚刚演奏的材料。也就是说，乐手通常操作的是“动机、目标音、句法和段落”，而不是孤立音符。([Frontiers][1])

这对你的软件非常重要：**用户不需要扮演一个技术不熟练的键盘手，而可以扮演一个实时作曲者或音乐导演。**

# 二、爵士即兴实际上在做什么

下面主要说有明确调性与和声进行的主流爵士，而不是完全自由即兴。

## 1. 底层框架通常已经存在

爵士乐手往往面对一个循环出现的曲式与和声进行，例如：

* 12 小节布鲁斯；
* 32 小节标准曲；
* ii–V–I 等局部句法；
* 一段固定的 bass、鼓和伴奏织体。

因此，即兴者不必同时发明全部音乐。他主要是在已有的时间轴上，决定如何解释这些和声。

## 2. 和声并不是“这个小节只能弹这七个音”

初学教材经常把爵士简化成：

> 看到 Dm7 就弹 D Dorian，看到 G7 就弹 G Mixolydian。

但真正决定连贯性的，通常不是音阶名称本身，而是：

* 当前和弦中的目标音；
* 这些目标音如何连接到下一和弦；
* 何时解决，何时故意延迟解决；
* 哪些外音是经过音，哪些外音正在暗示替代和声。

尤其是三音和七音这样的导向音，可以构成跨越多个和弦的连续声部线，使复杂和声仍然听起来有方向。([音乐理论在线][2])

例如：

```text
Dm7       G7       Cmaj7
F   →     F   →    E
C   →     B   →    B
```

即使旋律表面有很多经过音，听众仍能通过这些骨架音感知 ii–V–I。

## 3. 爵士即兴的主要控制层

一个爵士乐手大致同时控制以下几层：

| 层级   | 实际选择                        |
| ---- | --------------------------- |
| 曲式   | 当前在 A 段、桥段、结尾还是 turnaround  |
| 和声解释 | inside、延迟解决、替代和弦、altered、侧滑 |
| 目标音  | 下一拍或下一和弦要落在哪里               |
| 动机   | 重复、转位、移位、缩短、扩展、回答           |
| 节奏   | 提前、拖后、留白、切分、密度变化            |
| 能量   | 从稀疏到密集，从稳定到紧张，再回归           |
| 互动   | 回应鼓、贝司或上一位乐手的句子             |

动机发展是爵士独奏获得整体感的重要方式，但并不是每段爵士都必须高度动机化；有些风格更强调连续线条、音色、律动或者和声密度。([音乐理论在线][3])

## 4. 爵士即兴的真正难点

爵士难的不只是“选对音”，而是：

* 在时间压力下维持曲式位置；
* 同时听见当前和弦和下一和弦；
* 让句子有呼吸；
* 记住刚才弹过的材料；
* 使节奏与乐队形成关系。

即兴是一种在实时约束下同时进行生成、评价、听觉反馈与动作执行的活动，很多底层过程依赖经过训练形成的程序性记忆。([Frontiers][4])

你的软件恰好可以替用户承担其中最机械的部分：曲式追踪、落点计算、声部连接和具体演奏。

# 三、巴洛克管风琴即兴实际上在做什么

巴洛克键盘即兴与现代人想象中的“自由发挥”也不太一样。它更接近：

> 利用一套可组合的低音句法、终止式、序进、对位模式和装饰方法，实时完成一首符合体裁的作品。

通奏低音、无数字低音和 partimento 教学并不只用于伴奏，而是可以逐步通向前奏曲、众赞歌处理乃至赋格。([Cambridge University Press & Assessment][5])

## 1. 低音往往是结构骨架

巴洛克即兴者可以先想到一条低音线，例如：

```text
1 – 7 – 6 – 5
1 – 4 – 2 – 5 – 1
5 – 6 – 7 – 1
```

然后根据低音所处音级、运动方向和乐句位置，在上方实现合适的和声与声部进行。

“八度规则”一类方法，本质上提供了：

* 上行低音时，各音级常见的和声；
* 下行低音时，各音级常见的和声；
* 如何从一个调性区域平滑地走向终止式；
* 如何使内声部保持可演奏和相对自然。

但它不是固定和弦表，而是生成进一步变化的基础。

## 2. 巴洛克乐手会掌握大量句法模块

典型模块包括：

* 终止式；
* 五度序进；
* 低音下行或上行序列；
* 挂留链；
* 平行六度或十度框架；
* pedal point；
* 模仿入口；
* 固定低音变奏；
* 众赞歌旋律的分句处理；
* 主调与属调等近关系调之间的运动。

历史键盘教学可以把这些模块经过展开、变奏、延长和装饰，形成较完整的前奏曲或赋格段落。([音乐理论在线][6])

## 3. “作曲骨架”和“表面音符”是分开的

假设骨架只是：

```text
低音：1 — 4 — 2 — 5 — 1
```

它可以被实现成很多不同结果：

* 四声部和弦式；
* 两个声部的模仿；
* 右手连续十六分音符；
* 挂留与延迟解决；
* 旋律声部高度装饰；
* 左右手轮流出现短动机；
* 踏板保持属音，上方不断改变和声。

所以巴洛克即兴不是简单选择“下一个和弦”，而是同时考虑：

1. 低音和调性路线；
2. 终止式与段落位置；
3. 声部进行；
4. 对位或模仿关系；
5. 表面装饰和织体。

## 4. 不同体裁需要不同的即兴逻辑

### 自由前奏曲或托卡塔

用户主要控制：

* 调性区域；
* 紧张程度；
* 序进与终止；
* 织体密度；
* 快速音型和延长音之间的对比。

这是最适合你首先实现的巴洛克模式。

### 众赞歌前奏曲

已有一条众赞歌旋律，系统决定如何处理：

* 原样放在高声部、低声部或踏板；
* 对旋律进行装饰；
* 用旋律片段作为模仿动机；
* 每一句之前先做预模仿；
* 为不同乐句选择不同织体。

### 赋格

需要管理主题入口、调性应答、插部、紧接、声部数量和整体调性路线。历史上 partimento 与通奏低音训练确实能够通向赋格，但对实时系统来说，它显著复杂于普通和声填充。([Cambridge University Press & Assessment][7])

因此不建议把“完整巴洛克赋格即兴”作为第一个版本。

# 四、两种即兴最重要的共同结构

两种风格表面差异很大，但可以抽象成同一套层级：

```text
总体曲式
    ↓
当前段落目标
    ↓
调性与和声路线
    ↓
目标音 / 低音 / 对位骨架
    ↓
动机与节奏行为
    ↓
实际音符、配器和演奏细节
```

爵士更强调：

* 律动和节奏位置；
* 对固定 changes 的重新解释；
* 个人语汇；
* 与其他演奏者的即时关系。

巴洛克管风琴更强调：

* 低音句法；
* 终止式和序进；
* 声部独立性；
* 体裁与织体；
* 调性区域的清晰组织。

但二者都适合被设计成：

> 用户决定高层行为，算法完成低层实现。

# 五、最适合你的两维输入模型

你提出左右手各控制一个维度是可行的，但两个维度必须处于不同层级，否则组合很容易互相冲突。

我建议定义为：

## 维度 A：音乐往哪里走

也就是结构方向。

通用选项可以是：

* **停留**：延长当前功能；
* **推进**：走向属功能或下一段目标；
* **偏离**：进入邻近调或使用替代和声；
* **加压**：增加不稳定性，但暂不解决；
* **回归**：返回主调或当前局部主音；
* **收束**：开始终止式；
* **欺骗**：制造预期后转向其他区域。

爵士风格可以把它翻译成：

```text
Inside
目标导音
延迟解决
Altered dominant
三全音替代
短暂侧滑
回到 changes
```

巴洛克风格可以翻译成：

```text
延长主和弦
进入前属
五度序进
属持续音
进入近关系调
半终止
正格终止
假终止
```

## 维度 B：音乐怎样表达

也就是表面行为。

* 重复当前动机；
* 将动机上移或下移；
* 给出回答句；
* 增加留白；
* 增加密度；
* 缩短节奏；
* 扩展节奏；
* 上行；
* 下行；
* 模仿；
* 挂留；
* 装饰；
* 改变织体。

这样，用户可能选择：

```text
A：向属方向推进
B：重复动机并逐次上移
```

或者：

```text
A：暂时停留
B：降低密度并加入留白
```

这比“左手选和弦、右手选旋律音”更接近真正的即兴思维，也不会退化成简陋的键盘。

# 六、不要让用户在每一拍都必须选择

这是界面设计中非常关键的一点。

建议把操作分成三种时间尺度：

| 时间尺度      | 用户控制          |
| --------- | ------------- |
| 立即，约半拍至一拍 | 强调、留白、密度、延迟解决 |
| 短期，约一至两小节 | 动机变化、和声方向、织体  |
| 中期，约四至八小节 | 转调、高潮、终止、进入新段 |

如果用户没有操作，系统应当继续当前策略，而不是停下来或随机跳转。

也就是说，每个选择都具有一个默认的“惯性”：

```text
保持当前行为
继续发展
直到用户转向
或系统到达必须作出结构决定的位置
```

这会让用户感到自己在塑造音乐，而不是不断回答选择题。

# 七、候选不应该只是和弦名称

一个好的候选卡片至少应包含四层信息。

例如：

### 候选：暂时向属调靠近

```text
听感：推进感增强，尚未真正结束
理论：V/V → V
离调距离：轻度
预计持续：1–2 小节
返回难度：低
与当前动机：连续
```

### 候选：进入关系小调

```text
听感：色彩转暗，产生新的稳定中心
理论：vi 被重新解释为局部 i
离调距离：中等
预计持续：4–8 小节
返回难度：中等
与当前动机：可保留旋律轮廓
```

建议固定展示几个相对客观的感知维度：

* 稳定—不稳定；
* 停留—推进；
* 明确—含混；
* 接近主调—远离主调；
* 开放—收束；
* 稀疏—密集；
* 连续—对比；
* 常规—意外。

“温暖、忧伤、神秘”这样的描述可以保留，但不宜作为核心，因为它们高度依赖音色、速度、音区和个人联想。

核心描述最好由确定性的音乐特征生成，而不是完全交给语言模型自由描述。

# 八、相对音高与离调感应该怎样表示

这里不能只显示罗马数字，因为用户可能知道“V/V”，却没有立刻听出局部主音已经改变。

我建议系统同时维护三套坐标。

## 1. 全局主调坐标

始终以作品最初或用户指定的主音为参照。

例如在 C 大调中：

```text
F♯ = ♯4
D7 = II7 或 V/V
```

## 2. 局部主调坐标

如果当前暂时以 G 为中心：

```text
F♯ = 局部 7
D7 = 局部 V7
G = 局部 1
```

## 3. 当前和弦坐标

在 D7 中：

```text
D  = 根音
F♯ = 三音
A  = 五音
C  = 七音
```

所以同一个 F♯ 应显示成：

```text
全局：♯4
局部：7 of G
和弦：3rd of D7
```

这会比单一音级体系更清晰。

## 离调可视化

可以使用一个双层结构：

```text
外圈：原始主调 C
内圈：当前局部中心 G
路径：C → G
```

旁边显示：

```text
局部中心置信度：72%
持续时间：2 小节
状态：主音化，尚未确认转调
```

当局部中心持续更久，并出现明确终止式后，再把状态更新为：

```text
已确认转调至 G
```

调性认知模型通常会同时涉及局部与整体上下文；螺旋阵列等模型也可以用几何距离表示音、和弦和调之间的关系，以及局部中心与整体中心之间的张力。([King's College London][8])

不一定要直接采用复杂的三维螺旋图，但可以借用其“调性距离”思想。

# 九、适合你的算法架构

我不建议在第一版中使用神经网络直接生成全部音乐。更合理的是：

> 乐理系统负责生成合法且具有解释性的候选，轻量模型负责排序和个性化。

## 1. 音乐状态

每一时刻维护类似这样的状态：

```text
全局调性
局部调性及置信度
当前和弦与和声功能
低音音级
当前导向音
曲式位置
乐句位置
当前动机
当前织体
张力曲线
近期重复历史
用户最近的选择偏好
```

## 2. 高层动作，而不是直接搜索音符

搜索空间中的节点最好是：

```text
延长当前功能
转入前属
开始五度序进
短暂主音化 V
延迟终止
重复动机并上移
降低节奏密度
```

而不是：

```text
下一个音是 F♯4 还是 G4
```

高层动作确定后，再由 realization engine 生成具体音符。

## 3. 候选生成

你现有的乐理搜索系统可以先产生几十个内部候选，例如：

* 和声路径；
* 低音路径；
* 声部连接；
* 调性解释；
* 动机操作；
* 节奏模板。

然后将这些结果按听觉效果聚类，只展示 3–5 个真正不同的选项。

否则系统可能展示：

```text
选项 1：ii6–V
选项 2：ii65–V
选项 3：IV–V
选项 4：ii6–V7
```

对用户来说，它们很可能都是“进入前属并走向属”，不应占据四张卡片。

## 4. 硬规则与软规则分离

### 硬规则

只保留真正不能违反的条件：

* 超出乐器音域；
* 声部数量错误；
* 音符时值不闭合；
* 用户锁定的音符被修改；
* 某些体裁必要的主题位置；
* 明确指定的终止目标无法到达。

### 软规则

绝大多数传统规则应成为评分：

* 平行五度或八度；
* 声部交叉；
* 导音是否立即解决；
* 七音是否下行；
* 不协和音的准备与解决；
* 重复音过多；
* 和声节奏过快；
* 爵士中的所谓 avoid note；
* 动机连续性；
* 风格典型程度。

这样用户可以调节：

```text
历史风格严格度：80%
冒险程度：35%
对位清晰度：70%
色彩和声：45%
```

你的“删去古典乐理中过严限制”的思路是正确的，但最好不是删除规则，而是把它们从禁止条件改成可调成本。

## 5. 短期前瞻搜索

每次不要只计算下一个和弦，而应至少评估接下来一个短乐句。

例如：

```text
当前状态
 ├─ A：停留两拍后进入 V
 ├─ B：直接进入 V，但下一小节假终止
 ├─ C：先主音化 ii，再进入 V
 └─ D：五度序进，两小节后到 V
```

单独看第一个和弦，A 和 D 可能不明显；看到两小节路径后，区别才真正成立。

可以使用有限宽度的 beam search，并让乐理搜索提前计算接下来 2–4 小节。播放当前小节时，就可以准备下一组候选。

## 6. 轻量神经网络最适合做排序器

模型输入可以是符号特征：

```text
候选的调性距离
声部移动距离
是否包含终止式
当前张力与目标张力的差
动机相似度
节奏密度变化
风格语料中的出现概率
用户过去选择类似候选的频率
```

输出则是：

```text
这个用户在当前上下文选择该候选的概率
```

模型可以是很小的 MLP、GRU，或者紧凑的序列模型。它不需要独立创作，只要在乐理引擎生成的合法候选之间排序。

这种混合结构已经有相近思路：BacHMMachine 将调性和和弦转换的概率模型放在明确的乐理框架内，强调可解释性和较低计算负担；NeuralConstraints 则让神经模型作为候选偏好或启发式，与符号约束共同工作。([arXiv][9])

人机音乐共创研究也反复指出，创作者更需要可分解、可控制、可解释和可重新组合的系统，而不是只能一次生成完整结果的黑箱。([arXiv][10])

## 7. 后期可以加入“即时学习用户动机”

这是神经网络之外很有价值的一条路线。

用户可以：

* 哼唱一个短句；
* 在屏幕上点出节奏；
* 输入几个相对音高；
* 从刚才生成的音乐中圈选一小段。

系统把它作为当前会话的动机材料，进行：

* 截取；
* 重组；
* 延长；
* 缩短；
* 移调；
* 与新和声对齐。

OMax 一类实时机器即兴系统采用 Factor Oracle，从输入材料中寻找重复结构并实时重组，非常适合“从用户刚刚产生的素材继续发展”，而不需要重新训练大型模型。([IRCAM][11])

# 十、两种风格的具体交互可以这样设计

## 爵士模式

和声进行固定播放，左侧控制和声解释：

```text
稳定落在和弦音
沿导向音连接
增加延迟解决
使用 altered 色彩
短暂侧滑
回归原和声
```

右侧控制句法：

```text
重复
上移序进
下移序进
缩短
扩展
回答
留白
提高密度
```

例如当前是：

```text
Dm7 | G7 | Cmaj7
```

用户选择：

```text
左：G7 使用 altered 色彩，但延迟到 Cmaj7 第二拍解决
右：重复上一动机并缩短结尾
```

系统负责生成具体音符和节奏。

## 巴洛克前奏曲模式

左侧控制低音和调性路线：

```text
延长 i
走向 iv
五度序进
主音化 V
属持续音
半终止
正格终止
假终止
```

右侧控制织体与修辞：

```text
分解和弦
挂留链
模仿
上行音阶型
下行音阶型
回声
减少声部
增加声部
装饰高声部
```

例如：

```text
左：主音化 V
右：挂留链
```

系统就可以生成一个向属调靠近、内声部连续产生 4–3 或 7–6 挂留的两小节段落。

# 十一、输入设备怎样选择

## 第一版优先使用平板或手机

因为候选含义不断变化，需要：

* 动态文字；
* 实时听感描述；
* 调性状态显示；
* 候选试听；
* 手势操作；
* 历史路径回看。

平板上可以设计两个拇指区域：

```text
左拇指：结构方向
右拇指：表达方式
```

中心区域显示当前音乐状态和接下来一小节的时间线。

## MIDI 键盘可以作为可选控制器

不要让琴键继续代表绝对音高，而是映射成候选：

```text
C D E F：结构候选 1–4
G A B C：表达候选 1–4
黑键：返回、锁定、变体、试听、终止
延音踏板：保持当前策略
```

这样键盘只是触觉按钮阵列，不要求用户会弹琴。

## 3D 打印设备应放在交互模型稳定之后

比较适合的形态是：

* 左右各四个按键；
* 两个拇指滚轮；
* 一个“保持”键；
* 一个“回退”键；
* 压力条控制能量或密度；
* 小型屏幕，或者与手机配对显示动态标签。

纯粹使用固定标记的物理按钮不太合适，因为“候选 2”在不同上下文中可能代表完全不同的音乐行为。

# 十二、最合理的开发顺序

## 第一阶段：巴洛克自由前奏曲

这是与你现有和声搜索最接近的方向。

只实现：

* 大小调；
* 2–4 声部；
* 基本终止式；
* 前属—属—主；
* 五度序进；
* 局部主音化；
* 4–3、7–6 等挂留；
* 3–4 种表面音型；
* 每 1–2 小节一次结构选择。

它最容易验证：

> 用户是否真的会觉得自己在即兴，而不是在筛选算法结果。

## 第二阶段：爵士固定 changes 模式

先不要让用户同时改和声与独奏。

固定：

* 曲式；
* 和弦进行；
* bass 和鼓；
* 速度和律动。

用户只控制：

* 和声解释；
* 目标音策略；
* 动机变化；
* 节奏密度和留白。

## 第三阶段：开放和声

再允许用户在爵士中选择：

* 替代和弦；
* turnaround；
* 延长某个和弦；
* 插入 passing chord；
* 改变下一轮 chorus 的和声。

## 第四阶段：众赞歌与赋格

众赞歌前奏曲可以先做；完整赋格放到更后面。

# 十三、可以作为产品核心的一句话

你的软件不应是：

> “不会弹琴的人使用的简化键盘。”

而应是：

> **一个把即兴中的结构选择、听觉判断和具体演奏分离开的实时作曲乐器。**

用户负责：

* 想去哪里；
* 什么时候制造或释放张力；
* 保持还是改变材料；
* 当前句子应该继续、回答还是结束。

系统负责：

* 找到具体和声；
* 计算局部调性；
* 连接声部；
* 实现节奏；
* 填充装饰；
* 保证音乐能够继续进行。

这样用户仍然拥有真正的创作因果关系：音乐之所以转向、停留、加压或结束，是因为他作出了选择，而不是因为模型自行生成了一段“看起来不错的音乐”。
